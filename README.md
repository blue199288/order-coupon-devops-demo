# QoderWake × GitHub DevOps Demo

This repository is generated by the guided demo launcher. GitHub owns the event state machine; Global QoderWake owns the autonomous role execution.

## Demo journey

1. `Start QoderWake Demo` creates a Milestone and a requirement Issue.
2. Release Waker creates `iteration/<milestone>` and moves the Issue to `status:ready-dev`.
3. Developer Waker implements the Issue on a feature branch and opens a PR into the iteration branch.
4. Reviewer Waker runs only for `opened`, `reopened`, `synchronize`, and `ready_for_review` PR revisions. Comments and status changes do not wake it.
5. A human merges after the `[QW-REVIEW][sha][PASS]` marker appears.
6. Tester Waker verifies the iteration merge. In `fail-once` mode it creates one Bug and routes it back to Developer.
7. `Publish Iteration` asks Release Waker to open the iteration-to-main PR. After human merge, Release Waker tags the merge and closes the Milestone.

## Human operations in the demo

- Merge a PR only after Reviewer reports PASS and CI is green.
- Run `Publish Iteration` when all Issues in the Milestone are `status:verified`.
- Merge the generated release PR into `main`.

The four QoderWake invocation URLs are stored only as encrypted GitHub Actions Secrets.
